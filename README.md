# Електронний кабінет вихователя

Особистий застосунок вихователя коледжу. Інтерфейс і звіти — українською.
Початкова ціль — iPhone; спільна основа Flutter для Android, вебу, планшетів і комп'ютерів.
Робочі дані першої версії зберігаються локально на пристрої.

## Поточний стан — етап 02А: локальне зберігання

Для pull request і кожного push у `main` GitHub Actions виконує однакову
автоматичну перевірку на Flutter 3.35.4: отримання залежностей, перевірку
форматування, аналіз, тести та release-збірку web. Workflow не публікує
застосунок і не використовує жодних персональних даних.

Створено Flutter-застосунок із цілями iOS, Android і web. Початковий екран містить
позначку деморежиму, перемикач двох вигаданих класів, «Усі мої класи», пошук та
шість синтетичних учнів. У рядку видно клас, кімнату й спорт. Картка показує ПІБ
без обрізання, контакт учня та окремі контакти дорослих. Усі телефони демоданих
навмисно порожні, тому кнопки виклику заблоковані й показано «Номер не додано».

Дія зв'язку відокремлена адаптером: за наявності номера вона відкриває системний
набір, а коли він недоступний — копіює номер і пояснює це повідомленням. На
широкому екрані список і картка розміщуються поруч, на вузькому — відкривається
окремий екран. Підтримуються системна світла/темна тема та масштабування тексту.

Дані класів, учнів і контактів тепер проходять через інтерфейс репозиторію та
локально зберігаються у SharedPreferences як JSON зі `schemaVersion: 1`.
Синтетичний набір створюється лише за відсутності ключа під час першого запуску.
Пошкоджені дані, невідома версія формату або недоступне сховище показують
українське повідомлення з повторною спробою, не змінюючи збережений документ.
Декодер також відхиляє дублікати ID та учнів із посиланням на невідомий клас.

## Flutter SDK

Проєкт зафіксовано на Flutter **3.35.4 stable** (`.flutter-version`; Dart 3.9.x).
У чистому Linux-оточенні з `curl`, `tar`, `git` і Python 3:

```bash
./tool/install_flutter.sh
export PATH="$HOME/flutter/bin:$PATH"
```

Скрипт встановлює лише SDK, перевіряє версію наявного Flutter і не змінює
файли застосунку. `FLUTTER_HOME` дозволяє задати іншу директорію.
Після встановлення виконайте `flutter pub get` у корені репозиторію.
У хмарі задайте `CI=true` і `FLUTTER_SUPPRESS_ANALYTICS=true`, щоб вимкнути
визначення хмарного середовища через службову адресу та телеметрію:

```bash
export CI=true FLUTTER_SUPPRESS_ANALYTICS=true
flutter --no-version-check pub get
```

Lock-файл створений командою `flutter pub get` на Flutter 3.35.4 / Dart 3.9.2.
Проєкти платформ створені стандартною командою `flutter create`; повторювати її
для звичайного запуску не потрібно.

На macOS можна використати той самий номер версії через FVM:

```bash
brew tap leoafarias/fvm
brew install fvm
fvm install 3.35.4
fvm use 3.35.4
fvm flutter pub get
```

Для iOS додатково потрібні актуальні Xcode та CocoaPods. iOS-збірку слід
перевірити на Mac командою `fvm flutter build ios --no-codesign`;
у Linux вона не перевірялась.

## Запуск і перевірки

```bash
flutter pub get
flutter run -d chrome       # web
flutter run                 # підключений Android/iPhone
bash tool/check.sh          # залежності, формат, аналіз, тести, web
```

Етап 02А перевірено в GitHub Actions на Flutter 3.35.4 / Dart 3.9.2:
форматування без змін, аналіз без зауважень, **26 успішних тестів** та
release-збірка web. [Підтверджений запуск для `4e37125`](https://github.com/AlexMatsi/educator-cabinet/actions/runs/34348741011).

CI та хмарний агент використовують єдину команду `bash tool/check.sh`.
Вона перевіряє залежності з `--enforce-lockfile` та відсутність змін у
`pubspec.lock`. Для оновлення залежностей спочатку виконайте `flutter pub get`
та збережіть сформований lock-файл. Після кожної зміни агент перевіряє новий
запуск CI для актуального commit у PR, а не покладається на старий результат.

Тест повторного відкриття використовує справжній адаптер SharedPreferences із
підміною платформного сховища; він не замінює перевірку перезапуску застосунку
на фізичному iPhone. Результати вище отримано на runner GitHub Actions.
Тести охоплюють JSON round-trip, версію схеми, цілісність ID і `classId`,
помилки читання та запису, `false` від запису, збереження пошкодженого документа,
повторну ініціалізацію сховища та відсутність повторного seed. Також вони
перевіряють фільтр класу, повернення до всіх класів, пошук, прокрутку,
відкриття потрібної картки, відсутні номери, окремий виклик учню й дорослому,
помилки набору та буфера обміну, а також вузький екран із масштабом тексту 200%.
Системна дія підмінена в тестах: реальні дзвінки не виконувались.

Xcode, iOS Simulator і фізичний iPhone тут недоступні. Збірка iOS та Android
і робота системного набору на пристроях ще не перевірені. Робота зі справжніми
даними до цього етапу не належить.

Наступний етап 02Б: ручне редагування й адміністрування. Імпорт і харчування
навмисно не реалізовані зараз.

Розробка відбувається невеликими завершеними етапами. Після кожного етапу оновлюються цей файл і перевірений результат.

Облікові записи дітей, номери, сімейні та медичні відомості, заяви й робочі бази не є частиною репозиторію.
Для розробки використовуються лише вигадані дані.

## Обмеження локального прототипу

SharedPreferences тут призначений лише для синтетичних демонстраційних даних.
Шифрування, блокування доступу, резервне копіювання та синхронізацію не реалізовано.
Не слід покладатися на це сховище для критичних або справжніх персональних даних.
У web дані належать поточному браузеру й origin: очищення даних сайту або
приватний режим можуть призвести до їх втрати; між пристроями вони не переносяться.
Заміна сховища та захист даних потребують окремого етапу до реального використання.
