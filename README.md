# Електронний кабінет вихователя

Особистий застосунок вихователя коледжу. Інтерфейс і звіти — українською.
Початкова ціль — iPhone; спільна основа Flutter для Android, вебу, планшетів і комп'ютерів.
Робочі дані першої версії зберігаються локально на пристрої.

## Поточний стан — етап 02А

Побудовано прототип локального збереження класів, учнів і контактів. UI залежить
від інтерфейсу `StudentRepository`, а не від `shared_preferences`, тож майбутня
заміна механізму зберігання не вимагатиме переписування екранів. Перший запуск
зберігає синтетичні демодані як один JSON-документ зі `schemaVersion: 1`; повторне
відкриття читає саме збережене значення без повторного засівання.

Пошкоджений JSON, невідома версія схеми, помилка читання та помилка запису не
перезаписують наявне значення. Екран повідомляє про помилку читання без спроби
замінити дані демонабором. Редагування, імпорт і харчування до цього етапу не
належать.

`shared_preferences` тут є лише прототипним локальним сховищем і **не забезпечує
захист персональних даних**. Перед використанням реальних даних потрібен окремий
етап безпеки: захист доступу, шифрування та резервне відновлення.

## Flutter SDK

Проєкт зафіксовано на Flutter **3.35.4 stable** (`.flutter-version`; Dart 3.9.x).
У чистому Linux-оточенні з `curl`, `tar`, `git` і Python 3:

```bash
./tool/install_flutter.sh
export PATH="$HOME/flutter/bin:$PATH"
```

Скрипт встановлює лише SDK, перевіряє версію наявного Flutter і не змінює
файли застосунку. `FLUTTER_HOME` дозволяє задати іншу директорію.
Після встановлення виконайте `flutter pub get` у корені репозиторію.
У хмарі задайте `CI=true` і `FLUTTER_SUPPRESS_ANALYTICS=true`, щоб вимкнути
визначення хмарного середовища через службову адресу та телеметрію:

```bash
export CI=true FLUTTER_SUPPRESS_ANALYTICS=true
flutter --no-version-check pub get
```

Після зміни залежностей оновлюйте `pubspec.lock` командою `flutter pub get` на цій версії SDK.
Проєкти платформ створені стандартною командою `flutter create`; повторювати її
для звичайного запуску не потрібно.

На macOS можна використати той самий номер версії через FVM:

```bash
brew tap leoafarias/fvm
brew install fvm
fvm install 3.35.4
fvm use 3.35.4
fvm flutter pub get
```

Для iOS додатково потрібні актуальні Xcode та CocoaPods. iOS-збірку слід
перевірити на Mac командою `fvm flutter build ios --no-codesign`;
у Linux вона не перевірялась.

## Запуск і перевірки

```bash
flutter pub get
flutter run -d chrome       # web
flutter run                 # підключений Android/iPhone
dart format --output=none --set-exit-if-changed lib test
flutter analyze
flutter test
flutter build web
```

Перевірки етапу 02А охоплені тестами репозиторію: створення сховища, повторне
відкриття, серіалізація класів/учнів/контактів, пошкоджений JSON, невідома версія,
помилки читання й запису та відсутність повторного засівання. GitHub Actions у
[`.github/workflows/flutter.yml`](.github/workflows/flutter.yml) використовує
Flutter 3.35.4 і виконує `flutter pub get`, перевірку форматування, аналіз, тести
та `flutter build web` для PR і гілки `work`.

Локальна перевірка 2026-09-09 не виконана: Flutter/Dart SDK відсутній, а
`./tool/install_flutter.sh` не зміг отримати архів Flutter через HTTP 403. У CI
перевірки виконаються у чистому середовищі GitHub Actions. Xcode, iOS Simulator і
фізичний iPhone тут недоступні; iOS- та Android-збірки й системний набір на
пристроях не перевірені.

Наступний етап має залишатися окремим: ручне редагування та адміністрування.
Імпорт і харчування навмисно не реалізовані.

Розробка відбувається невеликими завершеними етапами. Після кожного етапу оновлюються цей файл і перевірений результат.

Облікові записи дітей, номери, сімейні та медичні відомості, заяви й робочі бази не є частиною репозиторію.
Для розробки використовуються лише вигадані дані.
