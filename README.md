# Електронний кабінет вихователя

Особистий застосунок вихователя коледжу. Інтерфейс і звіти — українською.
Початкова ціль — iPhone; спільна основа Flutter для Android, вебу, планшетів і комп'ютерів.
Робочі дані першої версії зберігаються локально на пристрої.

## Поточний стан — етап 02А

Створено Flutter-застосунок із цілями iOS, Android і web. Початковий екран містить
позначку деморежиму, перемикач двох вигаданих класів, «Усі мої класи», пошук та
шість синтетичних учнів. Ці дані тепер записуються лише під час першої
ініціалізації локального сховища та не відновлюються при наступних запусках або
помилці читання. У рядку видно клас, кімнату й спорт. Картка показує ПІБ
без обрізання, контакт учня та окремі контакти дорослих. Усі телефони демоданих
навмисно порожні, тому кнопки виклику заблоковані й показано «Номер не додано».

Дія зв'язку відокремлена адаптером: за наявності номера вона відкриває системний
набір, а коли він недоступний — копіює номер і пояснює це повідомленням. На
широкому екрані список і картка розміщуються поруч, на вузькому — відкривається
окремий екран. Підтримуються системна світла/темна тема та масштабування тексту.

Доступ до даних відокремлено інтерфейсом репозиторію. Локальна реалізація
зберігає класи, учнів і вкладені контакти одним JSON-документом із номером версії
схеми; послідовність міграцій передбачена в репозиторії для майбутніх версій.
Поки триває читання, інтерфейс показує український стан завантаження. За помилки
показує повідомлення і повторну спробу, не стирає наявний документ та не
підміняє його демоданими.

## Flutter SDK

Проєкт зафіксовано на Flutter **3.35.4 stable** (`.flutter-version`; Dart 3.9.x).
У чистому Linux-оточенні з `curl`, `tar`, `git` і Python 3:

```bash
./tool/install_flutter.sh
export PATH="$HOME/flutter/bin:$PATH"
```

Скрипт встановлює лише SDK, перевіряє версію наявного Flutter і не змінює
файли застосунку. `FLUTTER_HOME` дозволяє задати іншу директорію.
Після встановлення виконайте `flutter pub get` у корені репозиторію.
У хмарі задайте `CI=true` і `FLUTTER_SUPPRESS_ANALYTICS=true`, щоб вимкнути
визначення хмарного середовища через службову адресу та телеметрію:

```bash
export CI=true FLUTTER_SUPPRESS_ANALYTICS=true
flutter --no-version-check pub get
```

Lock-файл створений командою `flutter pub get` на Flutter 3.35.4 / Dart 3.9.2.
Проєкти платформ створені стандартною командою `flutter create`; повторювати її
для звичайного запуску не потрібно.

На macOS можна використати той самий номер версії через FVM:

```bash
brew tap leoafarias/fvm
brew install fvm
fvm install 3.35.4
fvm use 3.35.4
fvm flutter pub get
```

Для iOS додатково потрібні актуальні Xcode та CocoaPods. iOS-збірку слід
перевірити на Mac командою `fvm flutter build ios --no-codesign`;
у Linux вона не перевірялась.

## Запуск і перевірки

```bash
flutter pub get
flutter run -d chrome       # web
flutter run                 # підключений Android/iPhone
dart format --output=none --set-exit-if-changed lib test
flutter analyze
flutter test
flutter build web
```

Перевірка етапу 02А у Linux:

- `git diff --check` — без помилок пробілів.
- Встановлення Flutter 3.35.4 через `./tool/install_flutter.sh` зупинилося через
  заборонений середовищем мережевий доступ до `storage.googleapis.com` (HTTP
  403). Flutter SDK у контейнері відсутній, тому `dart format`, `flutter analyze`,
  `flutter test`, `flutter build web` і оновлення `pubspec.lock` тут фактично не
  виконані. Їх необхідно виконати в середовищі з SDK та доступом до pub.dev перед
  об'єднанням PR.

У хмарному середовищі до Flutter-команд додано `--no-version-check`.
Тести охоплюють фільтр класу, повернення до всіх класів, пошук, прокрутку,
відкриття потрібної картки, відсутні номери, окремий виклик учню й дорослому,
помилки набору та буфера обміну, вузький екран із масштабом тексту 200%,
збереження класів, учнів і контактів, захист наявного документа від підміни при
помилці та відхилення непідтримуваної версії схеми.
Системна дія підмінена в тестах: реальні дзвінки не виконувались.

Xcode, iOS Simulator і фізичний iPhone тут недоступні. Збірка iOS та Android
і робота системного набору на пристроях ще не перевірені. Робота зі справжніми
даними до цього етапу не належить.

## Вибір і обмеження локального сховища

`shared_preferences` обрано як малу кросплатформну основу для поточного обсягу:
на iOS дані потрапляють у платформні preferences (`NSUserDefaults`), на Android
— у DataStore Preferences, а у web — у сховище браузера. Єдиний JSON-документ
зручний для невеликого довідника і не прив'язує спільні моделі до SQL або
конкретної платформи. Це не сервер і не синхронізація між пристроями.

Сховище не зашифроване та ще не має блокування, резервування, відновлення чи
перевіреного захисту персональних даних, тому справжні чутливі відомості вводити
не можна. У браузері дані належать конкретному профілю й origin: інший браузер,
профіль або адреса матиме окреме сховище. Приватний режим, очищення даних сайту,
політика браузера або нестача місця можуть зробити дані недоступними чи видалити
їх; гарантій довговічності файлової системи мобільного застосунку web не має.

Наступний невеликий етап може додати ручне редагування та адміністрування через
наявний репозиторій. Імпорт і харчування навмисно ще не реалізовані.

Розробка відбувається невеликими завершеними етапами. Після кожного етапу оновлюються цей файл і перевірений результат.

Облікові записи дітей, номери, сімейні та медичні відомості, заяви й робочі бази не є частиною репозиторію.
Для розробки використовуються лише вигадані дані.
