# Етап 01 — основа та швидкий доступ до картки

## Мета

Отримати невеликий працездатний Flutter-проєкт, який можна перевірити в хмарі й потім зібрати на Mac.
Обсяг: вибір класу → список учнів → картка → доступ до контактів.
Це демонстраційний етап на синтетичних даних, ще не версія для справжніх журналів.

## Реалізація

1. Перевір наявність Flutter/Dart. Використай доступний актуальний stable SDK, перевір сумісність пакетів.
   Зафіксуй точну використану версію у проєкті та відтворюваний спосіб її встановлення в хмарному Linux-оточенні й на Mac.
   У разі недоступності SDK/мережі повідом причину замість багаторазових спроб.
2. Створи Flutter application у корені цього репозиторію, зберігши наявні документи.
   На цьому етапі потрібні цілі iOS, Android і web; desktop додається пізніше зі спільною логікою.
   Додай стандартний .gitignore, lock-файл застосунку і короткі інструкції.
3. Відокрем прості моделі учня, класу й контакту від демонстраційного джерела даних та віджетів.
   Використай стійкі синтетичні ID. Не прив'язуй особу до її прізвища або індексу рядка.
4. Додай 2 вигадані класи й загалом 6 демонстраційних учнів. Познач деморежим.
   Не використовуй справжніх дітей із розмови. Телефони у фікстурах порожні.
5. Початковий екран Учні: перемикач класу, Усі мої класи, пошук за ПІБ, рядки з класом, кімнатою та спортом.
6. Картка: повне ім'я без обрізання, телефон учня та Зателефонувати учню зверху; нижче імена/ролі дорослих з кнопками зв'язку.
   Відсутній номер відображай явно і блокуй виклик; не підміняй контакт.
   Підготуй системну дію дзвінка для валідного номера через окремий адаптер; при недоступності запропонуй копіювання.
   Віджети повинні дозволяти перевірити вибір правильного контакту через підставний адаптер без справжнього дзвінка.
7. Українські підписи, достатні області натискання, підтримка збільшення тексту, світла/темна тема.
   На вузькому екрані — переходи; на широкому — придатне компонування, без розтягування телефонної картки на всю ширину.

## Межі етапу

Харчування, редагування/імпорт, постійне збереження, чутливі відомості, звіти та онлайн-режим залишаються наступними етапами.
Не додавати удавано робочі журнали чи порожні сторінки всіх майбутніх модулів.
Не налаштовувати публічний хостинг, платні сервіси, Apple signing або TestFlight в цій хмарній задачі.
Нижню навігацію повного продукту додавати разом із відповідними робочими модулями.

## Перевірка та результат

- Форматування Dart, flutter analyze, змістовні flutter test.
- Перевір вибір класу/пошук, відкриття потрібної картки, відсутній номер та вибір адресата дзвінка.
- За доступності SDK виконай flutter build web. Це перевірка кросплатформенного коду, без публікації.
- Окремо зазнач, що збірка й запуск iOS на Mac/телефоні ще не перевірені.
- Онови README точними командами, версією SDK, виконаними перевірками та обмеженнями.
- Підготуй окрему гілку й pull request із коротким описом готового результату.
- Наступний етап: локальне збереження, ручне редагування й адміністрування; потім імпорт та харчування.
