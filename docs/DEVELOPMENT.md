# Хмарна розробка

## Узгоджений робочий процес

Користувач ставить завдання й перевіряє зручність застосунку в одному основному
чаті проєкту. GitHub зберігає код, документи етапів і результати CI. Робота
хмарного агента не залежить від увімкненого особистого Mac користувача.

1. На початку перевір поточні `main`, робочий PR і його head SHA через GitHub.
   Локальна копія або повідомлення попереднього чату можуть бути застарілими.
2. Продовжуй один робочий PR для погодженого етапу. Не створюй паралельних
   реалізацій того самого завдання. Перед записом повторно перевір head SHA;
   при сторонніх змінах перечитай їх і узгодь свою правку з ними.
3. Заверши невеликий етап, переглянь diff і запусти `bash tool/check.sh`.
   На Linux установи Flutter версії з `.flutter-version` через
   `bash tool/install_flutter.sh` або готове середовище з цією версією.
4. Сам підготуй commit/PR і перевір GitHub Actions для його актуального SHA.
   Якщо CI помилковий, виправ причину в цій самій гілці; не вимикай перевірку.
5. У межах дорученої користувачем інтеграції заверши PR після перевірки diff,
   успішних обов'язкових перевірок і усунення блокувальних зауважень.
   Під час merge передавай очікуваний head SHA. Дотримуйся правил GitHub і
   чинних дозволів; цей документ сам по собі не надає нових прав.
6. Онови стан етапу та повідом користувачу: що готово, що перевірено, що
   треба подивитися в інтерфейсі. Наступні функції виконуй у межах погодженої
   мети. Не проси користувача переносити завдання чи вручну створювати PR.

## Перевірки та обмеження

- `tool/check.sh`: перевірені за lock-файлом залежності, форматування,
  статичний аналіз, тести й release-збірка web. CI виконує той самий скрипт.
- Для зміни залежностей виконай `flutter pub get`, перевір і закоміть
  сформований `pubspec.lock`, після чого повтори `bash tool/check.sh`.
- Зелена web-збірка не підтверджує iOS. iOS потребує окремої сучасної macOS
  з Xcode; підпис і встановлення на фізичний iPhone — окрема перевірка.
- Для розробки використовуються синтетичні дані. Поточне SharedPreferences
  сховище є прототипом: використання справжніх даних потребує окремо
  перевірених захисту, резервування та відновлення за PRODUCT.md.
- Публікація, платні послуги й операції зі справжніми робочими даними
  виконуються лише в межах відповідного завдання користувача.

## Фонове супроводження

Фоновий запуск потребує окремо створеного завдання ChatGPT. Сам запис у цьому
файлі, відкритий чат або CI не запускають агента безперервно.

Кожен фоновий запуск перечитує цей документ, поточний PR і CI у GitHub.
Він продовжує тільки вже погоджену роботу. За відсутності активного етапу
не вигадує нових функцій і не змінює репозиторій. Якщо потрібне рішення
користувача або доступ недоступний, описує точну перешкоду й зупиняється.
Не повторює однакові повідомлення, не запускає другий процес редагування
того самого PR і не послаблює захист репозиторію.
